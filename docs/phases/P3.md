# P3 — الإجازات والأرصدة (قلب النظام)

> **التصميم والمعمارية:** التزم بـ DESIGN_SYSTEM.md (كل شاشة تشتغل Light وDark وRTL، توكنز فقط) وبـ ARCHITECTURE_MODULES.md (الكود يتحط في وحدته وبيتسجل في registry). أرفق لقطة/وصف للشاشة في الوضعين في التقرير.

المدخلات: الكود الحالي (P2 مقبولة) + SPEC_COMPACT.md (قواعد العمل 1-10)
المطلوب:
1. services/leaveCalculator.ts: حساب الأيام (عطلة أسبوعية + holidays + counts_weekends) — دوال نقية قابلة للاختبار.
2. services/balanceService.ts: المتبقي، المحجوز، توزيع الطلب العابر لسنتين، إنشاء leave_balances عند الحاجة (من leave_types).
3. شاشة طلب إجازة: اختيار موظف/نوع، عرض الرصيد الحالي، من/إلى، الأيام أوتوماتيك، السبب، الحالة. (رفع الاستمارة في P4.)
4. شاشة سجل الإجازات: بحث، فلتر نوع/حالة، اعتماد/رفض/إلغاء بنقرة.
5. لوحة التحكم الحقيقية: الكروت الأربعة + "أرصدة قربت تخلص" + آخر الطلبات.
6. أعمدة الأرصدة في صفحة الموظفين تصبح (مستخدم/متبقي) حقيقية.
7. اختبارات آلية (vitest) على leaveCalculator و balanceService تغطي الحالات التالية:
   - فترة فيها جمعة وسبت → تُستبعد
   - عطلة رسمية داخل الفترة → لا تُحسب
   - رصيد 2 وطلب 3 → رفض (وقبول مع "تجاوز بسبب")
   - طلب 2024-12-30→2025-01-03 → توزيع على سنتين
   - إلغاء طلب معتمد → الرصيد يرجع
   - طلبان متداخلان → رفض
   - مرضي بدون مرفق → لا يُعتمد
شروط القبول: كل الاختبارات تنجح + تجربة يدوية للشاشات. لا أرقام استحقاق في الكود.
